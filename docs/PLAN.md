# 기획안

> 업체 말고 커플 편에 서는 결혼 준비 계산기.
> 공개된 지역 평균 가격을 기준으로, 상담에서 받은 견적이 적정한지와 숨은 추가금까지 미리 알려 준다.

## 1. 문제
- 웨딩 업체, 특히 스드메는 가격을 미리 공개하지 않는다. 상담에 가야 견적을 알 수 있고, 계약 직전이나 뒤에 추가금이 붙는다.
- 커플은 상담에서 들은 금액이 비싼지 싼지 판단할 기준이 없다.
- 기존 웨딩 플랫폼은 업체가 광고주라 업체에 불리한 정보를 보여 주기 어렵다.

## 2. 접근 방식
- **업체 협조 없이**: 업체에게 견적을 받거나 입점시키지 않는다.
- **사용자 데이터 공유 없이**: 다른 커플의 견적서 공유에 기대지 않는다.
- **공개 데이터 활용**: 한국소비자원 [참가격](https://www.price.go.kr)의 결혼서비스 가격 조사(전국 14개 지역, 항목별 중간값)를 기준선으로 쓴다.
- **혼자 써도 첫날부터 쓸모 있게**: 커플이 직접 입력한 상담 견적을 지역 평균과 비교한다.

### 포지셔닝: 중개업체와의 차이
> 중개업체를 쓰든 안 쓰든, 계약 전에 한 번 확인하는 곳 (견적의 세컨드 오피니언)

아이웨딩 같은 중개업체는 제휴 업체와 가격을 미리 정해 두고, 계약이 성사되면 업체에게서 수수료를 받는다. 그래서 가격을 보여 줄 수 있지만, 제휴 업체끼리만 비교하고 자기 상품이 비싸다고 말하기 어렵다.

| | 중개업체 | 이 서비스 |
|---|---|---|
| 수익원 | 업체 수수료 | 업체에서 돈을 받지 않음 |
| 비교 범위 | 제휴 업체끼리 | 어느 업체 견적이든, 중개업체 패키지 포함 |
| 추가금 | 업체 정보 제공 | 빠진 추가금과 최종 예상 금액을 커플 입장에서 점검 |
| 계약서 | 제휴 업체 계약 진행 | 불리한 조항 점검 (3단계) |

- **경쟁하지 않을 영역**: 실제 할인가, 플래너 동행, 원스톱 계약. 사람과 제휴 계약이 필요한 영역이다.
- **업체·중개업체 가격 데이터는 쓰지 않는다**: 경쟁사 앱의 공개 가격을 가져다 쓰면 이용약관·저작권 문제가 생길 수 있다. 공공 데이터만 기준선으로 쓴다.

### 타깃
- **핵심: 플래너 없이 직접 준비하는 커플**. 비교 기준이 없어 가장 절실하다.
- **보조: 중개업체를 쓰는 커플**. 플래너가 추천한 패키지가 괜찮은지 확인하려고 쓴다.

## 3. 첫 업종: 스드메 + 웨딩홀
- **스드메**: 항목이 스튜디오, 드레스, 메이크업 3개로 단순하고, 가격이 불투명하다는 불만이 가장 큰 영역이다.
- **웨딩홀**: 결혼 비용에서 가장 큰 비중(식대)을 차지해 빠질 수 없다. 총액이 아니라 1인당 식대와 대관료로 나눠 비교한다.
- 참가격에 두 업종 모두 지역별 가격이 있어 바로 비교할 수 있다.

## 4. 로드맵

| 단계 | 기능 |
|---|---|
| **MVP (3개월)** | AI 일정·체크리스트, 지역별 스드메·웨딩홀 평균, 상담 견적 비교, 웨딩홀 비교, 숨은 추가금 예측, 날짜별 비용 차이, 커플 공유 |
| **2단계** | 식장 스타일 기반 모바일 청첩장 |
| **3단계** | 계약서 점검(비전 LLM) |
| **보류** | 축의금 손익 계산기, 커뮤니티, 박람회 정보 |
| **제외** | 상담 녹음 요약, 업체 입점형 견적 비교, 사용자 견적서 공유 |

## 5. MVP 기능

### AI 일정·체크리스트
- 결혼 예정일 기준으로 할 일과 마감일을 만든다.
- 커플이 할 일 담당자를 나눈다.

### 지역별 스드메·웨딩홀 평균
- 지역을 고르면 스튜디오, 드레스, 메이크업, 웨딩홀 1인당 식대·대관료의 중간값과 전국 평균, 데이터 기준 시점을 보여 준다.

### 상담 견적 비교
- 업체명, 상담일, 항목별 금액, 포함 옵션, 메모를 입력한다.
- 견적 출처(직접 상담, 중개업체 패키지)를 구분한다. 패키지는 묶음 가격이라 항목별로 나눠 입력해야 평균과 비교할 수 있다.
- 상담 전에 물어볼 질문 리스트를 업종별로 제공한다.
- 상담한 업체들을 지역 평균선과 함께 항목별 ± 금액으로 비교한다.

### 웨딩홀 비교
- 홀명, 1인당 식대, 대관료, 보증 인원, 포함 옵션(꽃장식, 폐백실, 주차 등)을 입력한다.
- 예상 하객 수를 넣으면 홀별 총비용을 계산하고, 1인당 식대와 대관료를 지역 평균과 각각 비교한다.
- 보증 인원보다 하객이 적을 때 생기는 손해를 보여 준다.

### 숨은 추가금 예측
- 업종별로 자주 붙는 추가금 목록을 둔다. 예: 스튜디오 원본·수정본, 드레스 피팅비·헬퍼비, 메이크업 얼리스타트·출장비, 웨딩홀 꽃장식 업그레이드·연출비·보증 인원 초과.
- 견적 입력 시 각 항목이 포함인지 체크하고, 빠진 항목은 "상담 때 확인 필요"로 표시한다.
- 추가금까지 넣은 **예상 최종 금액**을 보여 준다.

### 날짜별 비용 차이
- 예식 시기에 따라 평균 비용 차이(소비자원 자료 기준 최대 325만 원)를 보여 준다.
- 예정일을 입력하면 다른 시기로 옮길 때 예상 절약액을 보여 준다.

### 커플 공유
- 초대 링크로 두 사람이 같은 데이터를 함께 보고 수정한다.

## 6. 화면 흐름
1. **시작**: 결혼 예정일, 지역(참가격 14개 지역), 예상 하객 수, 예산 입력
2. **홈**: D-day, 이번 주 할 일, 예산 대비 견적 합계
3. **일정/체크리스트**
4. **지역 평균**
5. **상담 기록**: 스드메·웨딩홀 견적 입력, 포함 옵션 체크, 질문 리스트
6. **비교표**: 업체·홀별 금액, 평균 대비 차이, 추가금 포함 예상 최종 금액

## 7. 데이터 구조 (최소)
- `couple`: 예정일, 지역, 예상 하객 수, 예산, 멤버 2명
- `task`: 제목, 마감일, 담당자, 완료 여부
- `region_price`: 지역, 항목(스튜디오/드레스/메이크업/1인당 식대/대관료), 중간값, 기준 시점 (참가격 발표 때마다 직접 입력)
- `period_price`: 예식 시기, 평균 비용 (날짜별 비용 차이용)
- `extra_fee`: 업종, 항목명, 대략 금액 (추가금 목록)
- `consultation`: 업종(스드메/웨딩홀), 업체명, 견적 출처(직접/중개업체), 항목, 금액, 포함 옵션, 메모. 웨딩홀은 1인당 식대, 대관료, 보증 인원

## 8. 기술 스택
pnpm 모노레포, 언어는 TypeScript 하나로 웹·앱·계산 로직을 모두 쓴다.

```
apps/web        Next.js 16 (App Router, Cache Components) - 웹
apps/mobile     Expo (React Native) - 앱. 9주차부터 만든다
packages/core   가격 비교·추가금·웨딩홀 총비용 계산 (웹·앱 공유)
supabase/       DB 스키마와 RLS 정책
```

- **Supabase**: 로그인, DB, 커플 공유 권한(RLS)을 웹과 앱이 함께 쓴다. 별도 백엔드 서버를 두지 않는다.
- **웹 레이어**: 화면(`app`) → 조립 지점(`server/container.ts`) → 유스케이스(`server/application`) → 저장소 구현(`server/infrastructure`). Next.js 공식 Data Access Layer 권장 방식을 따른다.
- **웹과 앱의 역할**: 웹은 검색으로 사용자를 데려오는 입구, 앱은 일정 알림·상담 기록처럼 계속 쓰게 만드는 도구.
- **LLM API**: 체크리스트 생성. 3단계 계약서 점검에서 비전 LLM으로 사진 속 조항 추출
- **배포**: Vercel
- **코드 리뷰**: 코드를 바꾸면 보안 중심 `code-reviewer` 에이전트가 반드시 리뷰한다 (`.claude/`).

Supabase 무료 플랜: 월간 활성 사용자 5만 명, DB 500MB, 파일 저장 1GB, 전송량 5GB, 활성 프로젝트 2개. 1주일 동안 사용이 없으면 프로젝트가 일시 정지된다. MVP 테스트에는 충분하고, 정식 출시 때 Pro(월 25달러)를 검토한다.

## 9. 일정 (MVP 3개월)
| 기간 | 할 일 |
|---|---|
| 1~2주 | 모노레포·웹·DB 골격(완료), 참가격 데이터 정리, 추가금 목록과 상담 질문 리스트 작성, 와이어프레임 |
| 3~5주 | 웹: 시작 화면, 체크리스트, 지역 평균, 날짜별 비용 차이 |
| 6~8주 | 웹: 상담 기록, 스드메·웨딩홀 비교표, 추가금 예측, 커플 공유 |
| 9~11주 | 앱(Expo): 상담 기록, 비교표, 일정 알림 |
| 12주 | 결혼 준비 중인 지인 5~10쌍 테스트와 피드백 |

## 10. 주의할 점
- **같은 조건 비교**: 평균은 기본 패키지 기준이라 포함 옵션을 체크해 구분해야 한다. 웨딩홀은 총액이 아니라 1인당 식대와 대관료로 나눠 비교한다.
- **일정 여유**: 웨딩홀이 MVP에 들어와 범위가 커졌다. 3개월이 빠듯하면 날짜별 비용 차이를 뒤로 미룬다.
- **데이터 한계**: 지역 단위 평균이라 특정 업체가 비싼지까지는 알 수 없다. 화면에 "참고 기준"임을 명시한다.
- **이용 조건**: 참가격 데이터 재사용 시 출처 표기 조건(공공누리 유형 등)을 확인한다.
- **계약서 점검**: 법률 자문처럼 보이지 않도록 "참고용, 확인이 필요한 조항"으로 표현한다.
